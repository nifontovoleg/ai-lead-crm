# Подключение рабочего режима

Ключ ProxyAPI уже перенесён в локальный env проекта. Рабочие запросы выключены. Не отправляйте ключи и токены в чат.

## Google Sheets

Создайте собственную Google таблицу для подключения.

Открывать её нужно под Google аккаунтом, подключённым к Google Drive в Codex. Встроенный браузер во время проверки использовал другой аккаунт и показал отсутствие доступа. Общий доступ не включался.

1. В Google Cloud создайте или выберите проект и включите Google Sheets API.
2. Создайте сервисный аккаунт для этой CRM, выпустите JSON ключ. Сохраните файл в `secrets/google-service-account.json` внутри проекта. JSON не публикуйте и не отправляйте в чат.
3. В JSON найдите `client_email` и выдайте этому адресу редактирование подготовленной таблицы. Не включайте доступ всем по ссылке.
4. ID созданной таблицы уже внесён в локальный env. Выполните `.venv\Scripts\python.exe -m crm.cli check` — параметр service_account_file_present должен стать true.
5. Выполните `.venv\Scripts\python.exe -m crm.cli init-sheets`. Существующие лиды сохраняются. Рабочие колонки J:R заполняет приложение; A:I редактирует менеджер.

Эти шаги выполняются в аккаунте владельца проекта. Доступ Codex к Google Drive не выдаёт приложению Python собственные учётные данные.

## Telegram

1. Создайте отдельного бота через BotFather, сохраните токен в TELEGRAM_BOT_TOKEN локального env.
2. Откройте бота от имени менеджера и нажмите Start. Без первого обращения бот не сможет написать пользователю.
3. Укажите ID своего чата менеджера в TELEGRAM_CHAT_ID. Для группы добавьте бота и укажите ID группы. Сервис не запускает polling и не читает переписку.
4. Повторите команду check. Вывод подтверждает только наличие параметров; реальную доставку нужно проверить отдельно.

## Первый рабочий прогон

После разрешения на платную проверку: выставить CRM_MODE=live, MAX_LEADS_PER_RUN=1 и LIVE_PROCESSING_ENABLED=true. Запустить `.venv\Scripts\python.exe -m crm.cli process` один раз. Проверить исходную строку в Google Sheets, объяснение и рекомендацию, затем сообщение в Telegram. Не повторять неудачный запрос автоматически.

После успешного прогона повторный запуск проверяет отсутствие дублирующей отправки и продолжает обработку следующих лидов в рамках лимита. До публичного HTTPS размещения можно запускать обработку вручную. Для расписания требуется отдельное подключение Apps Script по README.
