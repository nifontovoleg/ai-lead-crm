# Проверка рабочего режима и запись демонстрации

Этот список заполняется только по фактической проверке. Локальное демо не закрывает пункты внешних интеграций.

- [ ] ТЗ DOCX открыто и визуально проверено в Word либо совместимом редакторе.
- [ ] Google таблица содержит листы Лиды и Dashboard и только вымышленные данные.
- [ ] Один лид получил оценку через реальный ProxyAPI; видны объяснение и рекомендация.
- [ ] Горячий лид вызвал сообщение в реальном Telegram чате менеджера.
- [ ] Повторный запуск не создал второй запрос модели и второе уведомление.
- [ ] Изменение активности либо бюджета переоценило только изменённого лида.
- [ ] Некорректные строки и дубликаты ID исключены из оценки.
- [ ] Dashboard соответствует данным и показывает диаграмму.
- [ ] Ручной вызов Apps Script завершился успешно.
- [ ] Установленный триггер выполнился по расписанию; затем показана остановка.
- [ ] Настройки содержат безопасные лимиты и постоянное хранилище журнала доставок.
- [ ] Открытый GitHub репозиторий доступен без авторизации и не содержит секретов.
- [ ] Скриншоты и видео показывают все функции, без env, ключей и персональных данных.
- [ ] Ссылка добавлена в раздел Проект №2 копии Тетради карьерных действий.
- [ ] Ссылка на тетрадь фактически отправлена на проверку пользователем.

## Сценарий скринкаста

1. Показать название проекта и таблицу. Сказать, что клиенты вымышлены, а система помогает менеджеру выбирать очередность обработки заявок.
2. Добавить активного лида с источником Рекомендация, бюджетом 120000, четырьмя контактами за неделю, последним контактом один день назад и ответом Да.
3. Запустить обработку через меню CRM. Показать балл 100, объяснение, рекомендацию и пометку ProxyAPI с моделью.
4. Переключиться на Telegram менеджера и показать карточку этого лида. Не показывать BotFather и токен.
5. Повторить обработку. Показать отсутствие нового сообщения и ноль обработанных лидов в результате запуска.
6. Изменить бюджет и активность другого лида. Показать обновлённую оценку только этой строки.
7. Показать обработку некорректной строки и пропуск закрытой сделки.
8. Открыть Dashboard: число лидов, источники, статусы, актуальные приоритеты и диаграмма. Объяснить, что балл не является вероятностью сделки, а сумма бюджетов не является прогнозом выручки.
9. Показать выполнение Apps Script по расписанию и команду остановки. Не открывать Script Properties с секретом.
10. Показать открытый репозиторий, README и DOCX. До внешней проверки использовать для записи только демонстрацию с явной пометкой ДЕМО и не выдавать её за рабочие интеграции.
