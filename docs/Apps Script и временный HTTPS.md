# Подключение Apps Script к локальной CRM

Python запускается на этом компьютере. Для доступа Google Apps Script используется временный HTTPS адрес Cloudflare Quick Tunnel. Аккаунт и домен Cloudflare не требуются; адрес меняется при новом запуске туннеля. Компьютер должен оставаться включённым, оба процесса — работать.

## Запуск

В PowerShell из папки проекта:

```powershell
.\START-HTTPS.ps1 -KeepAlive
```

Оставьте окно работающим. По умолчанию платная AI обработка выключена. Доступны liveness /health и защищённая проверка Google Sheets /connection-check. Она не обращается к модели и не отправляет Telegram сообщения.

Адрес и CRM_TRIGGER_TOKEN для подключения записываются в `data/runtime/apps-script-properties.txt`. Этот файл содержит секрет: используйте его только локально и в настройках своего Apps Script, не публикуйте и не отправляйте в чат. Ключ ProxyAPI, токен Telegram и JSON Google в Apps Script переносить не требуется.

Скачан официальный cloudflared 2026.10.7, SHA256 проверен по digest релиза GitHub. Бинарный файл находится в .tools/cloudflared.exe и исключён из Git. Установка в систему не выполнялась.

## Установка скрипта в таблице

1. Откройте CRM таблицу под аккаунтом владельца.
2. Выберите Расширения → Apps Script. Откроется проект, привязанный к этой таблице.
3. Откройте локальный `apps-script/Code.gs`, скопируйте его содержимое и замените стандартный код в редакторе Apps Script. Сохраните проект с названием CRM автоматизация.
4. В списке функций редактора выберите setupConnection и нажмите Выполнить. Выдайте разрешения своему скрипту. Если появится непонятное предупреждение, остановитесь и пришлите скриншот без секретов.
5. В первом диалоге вставьте CRM_API_URL из локального файла настроек подключения, во втором — CRM_TRIGGER_TOKEN. Эти значения сохраняются в Script Properties проекта.
6. Скрипт выполнит GET /connection-check. После успешной проверки на листе Dashboard в J1:K5 появятся время проверки, связь с Python OK, число лидов и нулевые счётчики AI и Telegram.
7. После перезагрузки таблицы появится меню CRM с настройкой, проверкой связи, обработкой и расписанием.

Кнопка Deploy / Развернуть для этого сценария не нужна: Apps Script выступает клиентом Python, а не публичным веб приложением.

## Включение рабочего расписания

Этот шаг разрешает обращения к ProxyAPI при добавлении или изменении лидов. До отдельного разрешения на дальнейшие платные вызовы он не выполняется.

Остановите процессы в другом PowerShell командой STOP-HTTPS.ps1, затем запустите START-HTTPS.ps1 -KeepAlive -EnableScoring. Новый запуск даёт новый HTTPS адрес; обновите подключение через setupConnection. Проверьте ручную обработку и только затем вызовите installTrigger. Он создаёт расписание каждые пять минут, но откажется это делать, пока обработка выключена на сервере.

removeTrigger останавливает расписание функции processLeads, STOP-HTTPS.ps1 — только процессы этого проекта с проверкой пути исполняемого файла. По завершении демонстрации остановите оба механизма.

## Проверка

```powershell
.\.venv\Scripts\python.exe tools\check_https_connection.py
```

Успешная проверка: health HTTP 200, запрос без токена HTTP 401, запрос с токеном HTTP 200, lead_count соответствует таблице, ai_calls и telegram_calls равны нулю. Это подтверждает HTTPS доступ к Python, но не заменяет выполнение функции из Google Apps Script.
